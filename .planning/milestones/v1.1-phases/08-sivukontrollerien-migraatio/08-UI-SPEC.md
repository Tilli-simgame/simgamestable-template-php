# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Assessment: No New Visual Surface (Thin Contract)

This phase is a **backend wiring task**, not a UI phase. The ROADMAP's own "UI hint" for Phase 8 is `no`. This UI-SPEC.md was generated only because the automated ui-plan-gate keyword scanner produced a false-positive match — it matched the literal word "UI" inside the phase's "**UI hint**: no" annotation text, not any real UI content.

**What Phase 8 actually does:** it migrates 7 public PHP page controllers (`index.php`, `hevoset.php`, `hevonen.php`, `kasvatus.php`, `yhteystiedot.php`, `ajankohtaista.php`, `postaus.php`) from "inline-HTML controllers" (fetch data → require header.php → print raw HTML → require footer.php) to "data-only controllers" that fetch data and `require resolveThemePath('pages/X.php')`, delegating 100% of HTML rendering to the already-built theme templates in `public/themes/default/pages/*.php`.

**What Phase 8 explicitly does NOT do:**
- It does not design, restyle, or alter any markup, CSS, spacing, typography, or color. All visual/HTML surface for these 7 pages was already built in Phase 7 and lives in `public/themes/default/pages/*.php` + `public/themes/default/includes/*.php` + `public/themes/default/assets/css/style.css`.
- It does not add new UI states, components, or copy. Per success criteria #1–#2 (ROADMAP.md lines 187–188), pages must load "correctly" (i.e., **visually unchanged** from what Phase 7's templates already render) — this is a non-regression contract, not a new design contract.
- It does not touch admin UI.

**Authoritative visual source for this phase:** `public/themes/default/pages/*.php` (Phase 7 output). If a checker or executor needs to verify visual correctness, compare rendered output against what these templates already produce today (pre-migration, via the old inline-HTML controllers) — the bar is pixel/behavior parity, not a new design.

There is no Phase 7 UI-SPEC.md on disk to cross-reference (none was generated for that phase); the templates themselves are the source of truth.

## Non-Regression Checklist (replaces standard visual dimensions for this phase)

Because this phase has no new visual surface, the `gsd-ui-checker` and `gsd-executor` should treat the following as the pass/fail bar instead of the standard 6 dimensions:

- [ ] Each of the 7 migrated pages renders **visually identical** output to its pre-migration inline-HTML version, when the active theme is `default`.
- [ ] No inline HTML remains in any of the 7 controllers in `public/pages/` after migration (per CONTEXT.md D-04) — controllers contain only data-fetching logic, the Model B root-override hook, and the single `require resolveThemePath('pages/X.php');` delegation line.
- [ ] Model B root-override hook is present and identical in structure across all 7 controllers (per CONTEXT.md D-02), matching the existing `index.php`/`hevonen.php` pattern (`resolveThemePath('{file}.php')` at theme root + `!str_starts_with(THEME_PATH, THEMES_ROOT . 'default' . DIRECTORY_SEPARATOR)` guard).
- [ ] Switching `settings.active_theme` in the DB to the temporary test theme (CONTEXT.md D-06) changes the rendered appearance with zero controller code changes — proving success criteria #3. Test theme is deleted before phase close (D-07).
- [ ] 404 fallback (if `resolveThemePath()` ever returns `false`) matches the silent `http_response_code(404); exit;` convention already used in `public/pages/theme-page.php` — no new error page copy or styling is introduced.
